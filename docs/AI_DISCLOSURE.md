# AI 生成声明

本项目（Android NAS Lite）是 [完整版仓库](https://github.com/styisme/android-nas) 的精简版。为了开源协作的透明度，特此详细披露 AI 在本项目及上游完整版中的参与程度。

**核心声明：Lite 版 100% 的业务代码（Java、Python、HTML、YAML 等）直接来自完整版；而完整版 99% 以上的代码由 AI 直接输出。此外，Lite 版仓库自带的全部专属文档（包括本文档、README、SECURITY、CONTRIBUTING、CHANGELOG）以及精简用的 Python 脚本，均由 AI 根据人类指令直接生成。**

人类开发者在此过程中没有手写过任何一行核心业务代码，也没有手写过任何一篇文档。

---

## AI 参与的具体部分（Lite 版及完整版）

### 1. 完整版核心业务代码（Lite 版完整继承）
- **服务端核心**：`NasHttpServer.java`（路由/分片/流式解压）、`WebDavServer.java` / `FtpServer.java`（纯 Socket 协议栈）、`DatabaseManager.java`（SQLite 引擎）、`AuthManager.java`（Basic Auth 与路径拦截）、`index.html`（MD3 网页 UI 与交互）。
- **跨平台客户端**：手机端（相册自动备份、多协议、局域网扫描）、TV 端（Leanback 卡片流与焦点动画）、桌面端（Tkinter UI 与在线编辑）。
- **CI/CD 自动化**：基于 GitHub Actions 的矩阵编译与平铺直传机制、`sync_version.py` 版本注入脚本。

### 2. Lite 版专属精简脚本
- 生成 `lite-gen.py` 与 `fix-lite.py`：基于全量复制、精准删除与字符串匹配替换的逻辑，实现从完整版剥离高危与冗余功能，并自动修复残留的编译错误与 CI 矩阵残留项。

### 3. Lite 版全套专属文档
- **README.md**：重构产品定位，加入完整版与 Lite 版的对照矩阵，明确"跟随式维护"策略。
- **SECURITY.md**：剥离完整版的极高危警告，重新界定 Lite 版保留功能的安全边界（如明文传输、ZIP 资源消耗等）。
- **CONTRIBUTING.md**：重写贡献分流规则，明确哪些 PR 应该提交给完整版，哪些留给 Lite 版。
- **CHANGELOG.md**：制定 `<完整版版本号>-lite.<N>` 的独立版本号格式与记录模板。
- **本文档 (AI_DISCLOSURE.md)**：即本声明。

## 开发者（人类）负责的核心工作

- **产品定义与需求决策**：决定项目要包含哪些端、用什么协议、UI 风格长什么样，以及决定剥离哪些高风险或低使用率的功能（如远控、Root 全盘、Watch/Apple/Harmony 端），以维持 Lite 版"稳定、干净、可长期挂机"的定位。
- **编译与执行**：在 Android Termux 环境或 PC 上运行 AI 生成的精简脚本，使用 Mgit 提交代码并推送至 GitHub。
- **真机测试与反馈**：把编译好的 Lite 版 APK 安装到废旧手机、电视盒子、电脑上，测试文件上传/下载、WebDAV 映射、相册备份等核心功能是否正常，并将错误日志、闪退截图或 Markdown 渲染错误（如链接 404）反馈给 AI，由 AI 输出修复补丁。
- **兼容性与编译排雷**：发现并反馈因精简导致的变量未定义、UI 菜单残留等问题，由 AI 修正脚本规则或输出补丁代码。
- **最终验收与发版**：决定某个 Lite 版本是否达到发布标准。

## 已知的局限性

1. **边缘场景依赖人类测试**：AI 无法真机运行，因此必须依靠人类反复测试并反馈 Bug（例如不同路由器下 WebDAV 的兼容性、Android 不同厂商 ROM 的后台保活表现）。
2. **明文传输**：Lite 版保留了 NanoHTTPD 的明文 HTTP 传输。若在公共网络使用，请自建 SSH 穿透进行加密，或开启自签 HTTPS 框架。
3. **精简继承的 Bug**：由于 Lite 版是对完整版的字符串裁剪，如果完整版更新了某段代码的缩进或注释，可能导致精简脚本匹配失败，进而产生残留调用。因此每次重新精简后，都必须进行完整的编译和真机验证。
4. **保活能力受限**：Lite 版移除了所有的激进保活策略，仅保留前台服务和基础锁。在严苛的国产 ROM 上，后台服务被系统杀死的概率显著高于完整版。
5. **文档排版与链接的盲区**：AI 生成 Markdown 时容易写错仓库分支名（如把 `master` 写成 `main`）或路径，需要人类在预览时进行肉眼排雷与截图反馈。
